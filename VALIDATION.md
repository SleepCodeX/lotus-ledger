# Validation — Lotus Ledger 1.1.0

Verified on 2026-11-09.

## Build

The production jar builds with Java 25, Fabric Loom 1.19.3, Minecraft 26.2, Fabric Loader 0.19.5 and Fabric API 0.161.0+26.2.

All **20 JUnit checks** passed, with none skipped. They cover:

- Recorded catch examples and formatted coverage for all 12 species × four tiers.
- Current no-article, a, and an catch-message variants.
- Rejection of ordinary chat, quoted catches, fish, other players' discoveries and unknown tiers.
- Player/profile/main-versus-alpha separation and world-scoped buffering.
- Allow/cancel deduplication while preserving distinct identical packets.
- Complete menu parsing, comma-separated counts, explicit missing tiers and Undiscovered entries.
- Rejection of incomplete, malformed, duplicate-tier or contradictory menu data.
- Collection checkmarks without invented numeric counts.
- Authoritative menu corrections both upward and downward.
- Idempotent unchanged menu reopening.
- Menu baseline → next chat catch → correct tier/species/grand totals → save/reload.
- Protection against applying a snapshot first observed before a newer catch.
- Unknown onboarding guidance, HUD bounds and count formatting.
- Backup recovery, damaged-input preservation and invalid-data handling.

An independent comparison with NEU item repository commit f315a139f067c1ac65272b70b294336b5327038e verified all **48** frog/tier item names.

## Actual packaged-client validation

The installable jar was loaded in a separate disposable Minecraft 26.2 client with Fabric Loader 0.19.5 and no SkyHanni. No installed instance was changed.

The client checks verified:

1. Standalone startup and real proportional font glyphs.
2. Actual editor rendering, view buttons, dragging, closing and settings reload.
3. Preview catches never entering the saved collection.
4. Real Minecraft ItemStack/ItemLore components for all 12 collector species.
5. Exclusion of matching items in the player's inventory.
6. Stable menu import and cached parsing of unchanged components.
7. One incoming formatted catch updating the tier counter from 24 to 25 exactly once.
8. The corresponding displayed species total of 27 and grand total of 32, separately from four collected tier combinations.
9. Immediate catch persistence and reload from the actual test-client config file.
10. Reopened-menu correction to 7, unchanged reopening retaining 7, correction to 30, then the next chat catch producing 31.
11. A second profile remaining separate and the original profile retaining its counter.
12. Reuse of prepared HUD text between unchanged rendered frames.

The preview in docs/media and the screenshots generated by the client tests are captures from the real offline client with controlled test data. They are not live Hypixel screenshots.

## Limits and release contents

- Live Hypixel network arrival and the user's full modpack have not been exercised. The packaged test uses the production processing paths with controlled collector data and game-message fixtures at the verified-server boundary.
- Menu grammar was checked against a maintained SkyblockAPI frog parser. Numeric counts only overwrite when all four tiers of the relevant item are positively parsed. Unknown quantities remain unknown.
- A profile name must be available before data can be assigned safely. Enable the Profile and Area widgets and Player List Info.
- The production jar contains its own classes, font resources, license and notices. Game tests, SkyHanni classes, Minecraft and Fabric API are not bundled.
- The published jar is pinned to the SHA-256 of the locally tested artifact. GitHub also repeats source build, logic and real-client checks independently.
